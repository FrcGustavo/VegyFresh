# System documentation

Keep architecture, cross-unit contracts and operational migration guidance here. Unit-specific setup and commands belong with the owning unit and should be linked from system documentation.

Describe implemented behavior separately from deployment prerequisites and planned work. Every verification claim must state what was actually tested and its limits. Never include real credentials, tokens, account mappings or private environment values.

Update cross-unit paths and contracts together when their source changes. Do not use `openspec/` as maintained architecture documentation unless the user explicitly includes it.
